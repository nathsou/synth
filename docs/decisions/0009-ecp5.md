# 0009: ECP5 as a third family, verified without hardware

Status: Accepted (supersedes the ECP5 part of 0005)

## Context

0005 deferred ECP5 because there is no ECP5 board. Project Trellis documents
the family's bitstream, routing and timing well enough to build the whole flow
from its database, and the checks that do not need hardware (bit-exact
bitstreams against `ecppack` and `ecpunpack`, simulation of decoded
bitstreams against the source RTL, timing against nextpnr-ecp5's on the same
routed designs) cover what the iCE40 and Artix-7 flows check before they reach
a board.

## Decision

- ECP5 (LFE5U, LFE5UM, LFE5UM5G) is a third family, `arch-ecp5`, marked
  experimental until a design runs on a board.
- Trellis' database is read at run time, as prjxray-db is for Artix-7: from
  `--db`, `SYNTH_TRELLIS_DB`, or the Debian/Ubuntu package's location. It is
  not vendored. Trellis' tools are CI-only oracles (0002).
- Bitstreams are written byte for byte as `ecppack` writes them, and the
  configuration as nextpnr-ecp5 writes it, so that every difference from the
  reference flow is a deliberate one.

## Consequences

- CI installs `fpga-trellis` and `fpga-trellis-database` for the ECP5 suite
  (`tools/ci_ecp5.sh` and the `trellis` integration tests).
- Hardware validation stays open until a board (ULX3S, OrangeCrab, Colorlight
  i5/i9, …) is added; Phase 3's hardware criteria wait for it.
